# Next.js 14.2.35 Pin - Plan

## Goal Capsule

- **Objective:** Operators can run this public x402 demo on a Next.js 14.2.x patch that is no longer the deprecated 14.2.5 security line, without taking a major upgrade.
- **Means:** Pin `next` exactly to `14.2.35` and regenerate `package-lock.json` with `npm install` only (KTD1, KTD2).
- **Authority:** Session-settled user-directed decisions, then Product Contract requirements, then this plan. Existing GHSA-2464 mitigations stay in place even when `npm audit` still names that advisory.
- **Stop if:** Any file besides `package.json` and `package-lock.json` would change, any dependency besides `next` would be added or upgraded, a major Next.js or React bump is proposed, or `.github/workflows/` would be edited.
- **Execution profile:** One packaging unit. Smoke-first verification with the repo's existing install, build, posture test, and production-audit commands. Do not invent new tests.
- **Who finishes:** The implementer lands the pin and records verification plus remaining `next` advisories. The shipping caller opens one PR from `main`. The user merges. Merging triggers a Vercel Production deploy; do not merge, label, or deploy in this run.

## Product Contract

### Summary

Pin Next.js from `14.2.5` to `14.2.35` in `package.json` and regenerate `package-lock.json`. Keep React on `^18`, keep the `sharp >=0.35.5` override, and keep `images.unoptimized: true`. Report remaining `next` advisories; do not treat them as a reason to leave 14.2.x.

### Problem Frame

`14.2.5` is published as deprecated with a Next.js security notice. This repo already mitigates GHSA-2464 via the `sharp` override and unoptimized images, is outside the 16.x `use cache` range (GHSA-673q), and has no middleware or Server Actions (GHSA-p3m5). The remaining gap is staying on an older 14.2.x line.

### Key Decisions

- Stay on Next.js 14.2.x rather than 15.x or 16.x (session-settled: user-directed — chosen over a major upgrade: clear older 14.2.x advisories without changing the app's framework generation). Governs R1, R2.
- Keep the existing GHSA-2464 mitigations rather than removing them after the pin (session-settled: user-directed — chosen over changing the override or image config: those mitigations already cover the image-optimizer advisory that 14.2.35 does not patch). Governs R3, R4.
- Keep `react` and `react-dom` on `^18` (session-settled: user-directed — chosen over a React upgrade: this PR is a Next patch pin only). Governs R5.
- Leave `.github/workflows/` untouched (session-settled: user-directed — chosen over CI edits: the bump is a dependency pin, not a pipeline change). Governs R6.
- Record remaining `next` audit findings with their fixed-in versions instead of chasing a clean audit on 14.2.x (session-settled: user-directed — chosen over treating a remaining advisory as a reason to upgrade major: GHSA-2464 and GHSA-p3m5 are patched in 15.5.28 / 16.4.1, which this run rejected). Governs R8.

### Requirements

Pin and lockfile

- R1. `package.json` pins `dependencies.next` to the exact string `14.2.35`, not a caret, tilde, or other range.
- R2. `package-lock.json` is regenerated with `npm install` so the resolved `node_modules/next` version is `14.2.35`. No hand-edits.

Preserved mitigations and scope

- R3. `package.json` `overrides.sharp` remains `>=0.35.5`.
- R4. `next.config.mjs` keeps `images.unoptimized: true` and is not edited.
- R5. `react` and `react-dom` remain `^18`.
- R6. `.github/workflows/` is not created, edited, or deleted.
- R7. No other dependency is added, removed, or version-changed.

Reporting

- R8. The PR body states the before/after `next` versions, the results of the required verification commands, any remaining `npm audit --omit=dev` advisories whose package is `next` with each advisory's fixed-in version, and that merging triggers a Vercel Production deploy.

### Success Criteria

- `npm ci`, `npm run build`, and `npm test` (the existing `test/posture.test.mjs` suite) succeed after the pin.
- The PR body a reviewer reads can answer: what `next` was, what it is, whether build and tests passed, and which `next` advisories remain with their fixed-in versions.

### Scope Boundaries

In scope: `package.json` `next` pin and the lockfile regen that follows.

Deferred to Follow-Up Work: a later major upgrade that would take `next` to a line that patches GHSA-2464 and GHSA-p3m5 (fixed-in `15.5.28` / `16.4.1`).

Outside this work: React 19, removing the `sharp` override, enabling image optimization, Server Actions, middleware, new tests, README rewrites, workflow or Vercel config edits, merging, labeling, and deploying.

### Sources

- Current pin: `package.json` `dependencies.next` is `14.2.5`; lockfile `node_modules/next` is `14.2.5` and marked deprecated.
- App surface: `src/app/api/market-data/route.ts`, `src/app/api/sentiment/route.ts`; no `middleware` file; no Server Actions.
- Mitigations already present: `package.json` `overrides.sharp`, `next.config.mjs` `images.unoptimized: true`.
- `npm view next versions` on 2026-10-27: latest `14.2.x` is `14.2.35`.
- GitHub advisories: GHSA-2464-fhr4-w9xw (image optimizer; 14.2.35 still in range; patched `15.5.28` / `16.4.1`), GHSA-673q-mjm6-r5xr (`use cache`; 16.x only), GHSA-p3m5-59mp-jv5r (Server Actions DoS; 14.2.35 still in range; patched `15.5.28` / `16.4.1`).

- KTD1. Pin `next` to the exact version `14.2.35` (session-settled: user-directed — chosen over other 14.2.x versions or a version range: it is the latest 14.2.x patch as of `npm view` on 2026-10-27). Instantiates R1.

## Implementation Units

### U1. Pin next and regenerate the lockfile

- **Goal:** `package.json` and `package-lock.json` both resolve `next` to `14.2.35` and nothing else of substance changes.
- **Requirements:** R1, R2, R3, R5, R7. Cites KTD1, KTD2.
- **Dependencies:** none
- **Files:** `package.json`, `package-lock.json`
- **Approach:**
  1. Change only `dependencies.next` from `14.2.5` to `14.2.35`.
  2. Run `npm install` so the lockfile picks up that pin.
  3. Diff `package.json` and `package-lock.json`. Revert any drift that is not the `next` pin and its lockfile closure (overrides, React, TypeScript, and other deps stay as they are).
- **Execution note:** This is packaging. Prefer install and runtime smoke verification over new unit coverage.
- **Patterns to follow:** The existing exact `next` pin style (`"next": "14.2.5"`), not a caret range.
- **Test scenarios:**
  - Happy path: after install, `package.json` reads `"next": "14.2.35"` and the lockfile `node_modules/next` version is `14.2.35`.
  - Edge: `overrides.sharp` is still `>=0.35.5`; `react` and `react-dom` are still `^18`.
  - Error: if `npm install` mutates other dependency versions, those mutations are reverted or the install is redone so only `next` changes.
- **Verification:** The two named files are the only intended diffs. `npm ci` then succeeds on a clean install from the new lockfile.
